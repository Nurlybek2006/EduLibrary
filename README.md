# EduLibrary

EduLibrary — университеттің оқу әдебиеттері кітапханасын басқаратын ASP.NET Core MVC қосымшасы. Каталог, оқырмандар, кітап айналымы, жеке кітап ұсыныстары, бес есеп, талдау, пікірлер, QR іздеу және ішкі хабарландырулар SQL Server деректеріне сүйенеді. Кітап сипаттамасы мен физикалық дана бөлек сақталады. Интерфейс қазақ тілінде, ашық және қараңғы тақырыптарды қолдайды.

## Технологиялар

- .NET 10 LTS, ASP.NET Core MVC, Razor Views, C#.
- Entity Framework Core 10.0.12, SQL Server, Code First migrations.
- ASP.NET Core Identity: `Admin`, `Librarian`, `Student` рөлдері.
- Bootstrap 5, арнайы CSS/JavaScript, Lucide белгішелері, Chart.js графиктері.
- QRCoder: серверде QR SVG; браузерде BarcodeDetector немесе жергілікті ZXing сканері.
- xUnit unit tests және нақты SQL Server-де оқшауланған интеграциялық тексерулер.
- MVC → Service Layer → EF Core; сервистер Dependency Injection арқылы беріледі.

Бұл — жеке EduLibrary жобасы. `IntelligentProgrammingPlatform` жобасының файлдары өзгертілмейді.

## Жылдам іске қосу

Қажет: .NET 10 SDK, SQL Server және осы Windows пайдаланушысына деректер базасын жасау/пайдалану құқығы. SSMS 21 — базаны қарауға арналған құрал; SQL Server қозғалтқышы бөлек орнатылуы тиіс.

Жоба түбірінде PowerShell арқылы:

```powershell
dotnet --info
dotnet restore
dotnet tool restore --tool-manifest .\dotnet-tools.json
dotnet build
dotnet run --launch-profile http
```

Браузерде **http://localhost:5298** ашыңыз. HTTPS профилі: `dotnet run --launch-profile https`, мекенжайы **https://localhost:7296**. Жергілікті HTTPS сертификаты қажет болса: `dotnet dev-certs https --trust`.

`http` және `https` профильдері `Development` ортасын қосады. Осы ортада бірінші іске қосылғанда migrations автоматты қолданылады және бос база оқу деректерімен толтырылады. SQL Server қосылмаса, бағдарлама қатені журналға жазып тоқтайды; SQL орнына жалған деректерге ауыспайды.

## SQL Server қосылымы

Осы жұмыс орнында анықталған SQL Server default instance — `.`; қозғалтқыштың негізгі нұсқасы — 16. Деректер базасының аты — **EduLibraryDb**. Development конфигурациясы `appsettings.Development.json` ішінде; басқа компьютерде өз instance атауыңызды орнатыңыз.

| Орнатылым | Connection string мысалы |
|---|---|
| Default instance | `Server=localhost;Database=EduLibraryDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=False` |
| SQL Express | `Server=.\SQLEXPRESS;Database=EduLibraryDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=False` |
| LocalDB | `Server=(localdb)\MSSQLLocalDB;Database=EduLibraryDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=False` |

Development қосылымын user-secrets арқылы беру:

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=localhost;Database=EduLibraryDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=False"
```

`appsettings.Local.json` файлы тек Development ортасында оқылады және Git арқылы жіберілмейді. Қолданба оны user-secrets-тен кейін жүктейді: бірдей кілт local файлда болса, сол мән басым болады. User-secrets-ке көшірген кілттерді local файлдан алып тастаңыз. Environment variables және командалық жол аргументтері local файлдан басым.

Environment variable баламасы:

```powershell
$env:ConnectionStrings__DefaultConnection = "Server=localhost;Database=EduLibraryDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=False"
```

`TrustServerCertificate=True` мысалдары жергілікті әзірлеуге арналған. Production қосылымында сенімді SQL сертификатын, шектеулі құқықтары бар аккаунтты және сыртқы құпиялар сақтау орнын пайдаланыңыз; connection string пен парольдерді репозиторийге қоспаңыз.

### SSMS 21 арқылы қарау

1. SSMS 21 ашып, **Database Engine** түрін таңдаңыз.
2. Server name: `.` немесе өз SQL instance атауыңыз; Authentication: **Windows Authentication**.
3. Қосылғаннан кейін **Databases → Refresh → EduLibraryDb → Tables** ашыңыз.
4. `Books`, `BookCopies`, `Students`, `Loans`, `Returns`, `Fines`, `FinePayments` және `AspNetUsers` кестелерін қараңыз. `__EFMigrationsHistory` қолданылған migrations тізімін сақтайды.

Қосылым қатесінде SQL Server қызметінің іске қосылғанын, instance атауын және қолданбаны іске қосқан Windows аккаунтының SQL рұқсаттарын тексеріңіз. Базаны қолмен жасаудың қажеті жоқ: рұқсат болғанда EF migration оны жасайды.

## Migrations және бастапқы деректер

```powershell
$env:ASPNETCORE_ENVIRONMENT = "Development"
dotnet tool restore --tool-manifest .\dotnet-tools.json
dotnet ef migrations list
dotnet ef database update
```

Модельді кейін өзгерткенде жаңа migration жасаңыз; қолданыстағы migration тарихын өшірмеңіз:

```powershell
dotnet ef migrations add DescribeYourChange --output-dir Data/Migrations
dotnet ef database update
```

Веб-серверді ашпай, Development базасын дайындау:

```powershell
dotnet run --launch-profile http -- --initialize-db
```

`Database:ApplyMigrations` Development ортасында `true`, негізгі конфигурацияда `false`. Production ортасында migrations-ті басқарылатын орналастыру қадамы ретінде қолданыңыз; connection string-ті міндетті түрде сырттан беріңіз. `DbSeeder` барлық ортада рөлдерді тексереді, ал демо пайдаланушылар мен оқу деректерін тек Development ортасында жасайды.

Толық бастапқы жинақ: **36 кітап, 106 физикалық дана, 20 автор, 6 баспа, 9 санат, 18 студент, 6 пән**, студент қызығушылықтары. Демо қызметкер конфигурациясы берілсе, белсенді және қайтарылған **14 кітап беру жазбасы**, мерзімі өткен кітаптар мен айыппұлдар қосылады. Бұл сандар — бастапқы оқу жинағы; экрандар статистиканы SQL Server-ден есептейді.

Seed транзакциямен орындалып, `SeedHistory` белгісімен қайталанудан қорғалады. Бұрыннан кітаптары немесе студенттері бар базаға демо каталог араластырылмайды. Толық демо сценарий үшін `SeedUsers` мәндерін алғашқы толтыруға дейін беріңіз. Seed-ті қайта іске қосу бұрынғы аккаунттың паролін өзгертпейді.

Екінші кезеңнің migration-дары қолданыстағы базаға қосылады; `EduLibraryDb` өшіріліп қайта жасалмайды:

| Migration | Өзгеріс |
|---|---|
| `InitialFoundation` | Бірінші кезеңнің негізгі кестелері мен Identity |
| `IntelligentLibrary` | `BookSubjects`, `Notifications`, пікірді жасыру/soft delete/RowVersion, жаңа индекстер; бар санаттардан тек жетіспейтін пәндік байланыстарды толықтыру |
| `ReportingIndexes` | Беру, қайтару, төлем және ашық пікірлердің күндік сұрауларына индекстер |

Migration қолданылғаннан кейін негізгі деректердің сақталғаны расталды: **36 кітап, 106 дана, 18 студент, 14 беру, 5 қайтару, 3 айыппұл**. Кейін қолданба арқылы жасалған жаңа операциялар бұл сандарды табиғи түрде өзгертеді.

## Демо аккаунттар

Осы жұмыс орнында Development үшін жеке кездейсоқ парольдері бар `appsettings.Local.json` жасалған. Парольдерді тек өз компьютеріңізде қараңыз:

```powershell
Get-Content .\appsettings.Local.json
```

| Рөл | Development поштасы |
|---|---|
| Әкімші | `admin@edulibrary.local` |
| Кітапханашы | `librarian@edulibrary.local` |
| Студент | `student@edulibrary.local` |

Жаңа компьютерде аккаунттарды user-secrets арқылы конфигурациялауға болады. Төмендегі пароль орындарына өзіңіз жасаған әртүрлі құпиясөздерді жазыңыз:

```powershell
dotnet user-secrets set "SeedUsers:Admin:Email" "admin@edulibrary.local"
dotnet user-secrets set "SeedUsers:Admin:Password" "<әкімшінің жеке құпиясөзі>"
dotnet user-secrets set "SeedUsers:Librarian:Email" "librarian@edulibrary.local"
dotnet user-secrets set "SeedUsers:Librarian:Password" "<кітапханашының жеке құпиясөзі>"
dotnet user-secrets set "SeedUsers:Student:Email" "student@edulibrary.local"
dotnet user-secrets set "SeedUsers:Student:Password" "<студенттің жеке құпиясөзі>"
```

Құпиясөз кемінде 10 таңбадан тұрып, бас әріп, кіші әріп, сан және арнайы таңба қамтуы керек. Кодта production үшін бастапқы пароль жоқ. User-secrets әзірлеуге арналған; оны production құпиялар сақтау орны ретінде пайдаланбаңыз.

**Admin** барлық басқару модульдерін, пікір модерациясын және кітапханашы аккаунттарын басқарады. **Librarian** каталогты, оқырмандарды, кітап айналымын, есептерді, талдауды және сканерді пайдаланады; студент таңдап оның ұсыныстарын қарайды. **Student** каталогты, өзінің тарихын, айыппұлдарын, ұсыныстарын, хабарландыруларын көреді; өз пікірлерін, байланыс деректерін, пәндері мен қызығушылықтарын өңдейді. Академиялық факультет/курс/топты студенттің профиль формасы өзгерте алмайды.

Жаңа тіркелу тек `Student` рөлін береді. Бұрыннан тіркелген студент нөмірі арқылы басқа оқырманның жазбасын иемденуге болмайды. Белсенділігі тоқтатылған студентке жаңа кітап берілмейді; байланыстырылған аккаунт бұғатталады, тарих сақталады. Әкімші аккаунтын немесе өз аккаунтыңызды кітапханашылар тізімінен тоқтату мүмкін емес.

Басты маршруттар: `/Books`, `/Dashboard`, `/Students`, `/Loans`, `/Returns`, `/Fines`, `/Staff`, `/Recommendations`, `/Recommendations/Preferences`, `/Reports`, `/Analytics`, `/Reviews`, `/Copies/Lookup`, `/Notifications`, `/Account/Profile`. Студент өзінің тарихын `/Students/MyHistory` арқылы ашады; кіру/тіркелу — `/Account/Login`, `/Account/Register`.

## Кітап беру, қайтару және айыппұл

1. Қызметкер белсенді студент пен `Available` дананы таңдап, қайтару мерзімін береді.
2. `Loan` жазбасы мен дананың `OnLoan` мәртебесі бір транзакцияда сақталады.
3. Қайтарғанда бір ғана `Return` жасалып, дана жағдайына сай `Available` немесе `Damaged` болады.
4. Кешігу күндері `max(0, қайтарылған күн − DueDate)` формуласымен анықталады. Қайтарылмаған кітап үшін ағымдағы күн қолданылады және сома болжам ретінде көрсетіледі.
5. Қайтарғанда айыппұл сомасы бекітіледі. Қызметкер төлемді тіркегенде қалдық пен мәртебе жаңарады; бұл сыртқы банк төлем шлюзі емес.

Мысал: мерзімі 10 қазан, қайтару 15 қазан → 5 күн × 100 ₸ = **500 ₸**. Күндер кітапхананың **Asia/Qyzylorda** уақыт белдеуімен есептеледі; техникалық жасау/төлем уақыттары UTC-де сақталады.

Саясат `appsettings.json` арқылы конфигурацияланады:

```json
"Library": {
  "FinePerOverdueDay": 100,
  "DefaultLoanDays": 14
}
```

Қатар кітап беру `RowVersion`, транзакция және белсенді `Loan` үшін бірегей индекс арқылы қорғалған. Бір дананы екі рет қатар беру немесе бір қарызды екі рет қайтару қабылданбайды. Тарихы бар деректерді кездейсоқ жоюға FK шектеулері кедергі жасайды.

## Жеке кітап ұсыныстары

`/Recommendations` бетінде студент тек өзінің ұсыныстарын көреді. Қызметкер студентті тізімнен таңдайды. `/Recommendations/Preferences` бетінде қызығушылықтарды қосуға/алып тастауға және пәндерді таңдауға болады; сұраудағы басқа студент ID-і студенттің өз шектеуін айналып өтпейді.

Алгоритм `RecommendationService` және тесттелетін `RecommendationScoring` ішінде. Төрт фактор 0–1 аралығына келтіріледі:

| Фактор | Әдепкі салмақ | Нақты дерек |
|---|---:|---|
| Қызығушылық | 30% | Тақырып сөздерінің кітап атауы, сипаттамасы, санаты және пәнімен сәйкестігі; шағын қазақ/орыс/ағылшын ұғымдар сөздігі |
| Пән | 25% | Нақты `BookSubjects` байланысы; ол болмаса әлсіздеу мәтіндік сәйкестік |
| Оқу тарихы | 25% | Бұрынғы санат/автор/пәндер, беру саны және студенттің ашық бағалары |
| Танымалдық және рейтинг | 20% | Жалпы беру саны, пікір санына қарай салмақталған рейтинг, сол факультеттің беру тарихы |

**Сәйкестік = 100 × Σ(фактор × нақты салмақ)**. Дерегі жоқ жеке фактордың салмағы қалған факторларға қайта бөлінеді. Қызығушылық, пән және тарих түгел жоқ болса, cold-start режимі нақты танымалдық/рейтинг/факультет деректерін қолданып, жеке сәйкестік дәлелі аз екенін ашық жазады. Бос даналар алдымен көрсетіледі; тең нәтиже тұрақты ережемен сұрыпталады. Кездейсоқ баға немесе ойдан шығарылған кітап жоқ.

Қазір қолдағы кітаптар әрқашан алынып тасталады. Әдепкіде бұрын алынған және ашық пікір жазылған кітаптар да көрсетілмейді; «Бұрын оқылған кітаптарды да қосу» арқылы оларды қайта қосуға болады. Кітаптар архивтелмеген нақты каталогтан алынады. Бастапқы шек — 2000 кандидат, әр бөлімде 4 кітап; үлкен каталогта қаралған шек интерфейсте көрсетіледі.

Алты бөлім: **Сізге ұсынылады; Оқыған пәндеріңізге сай; Қызығушылықтарыңыз бойынша; Оқыған кітаптарыңызға ұқсас; Салаңызда танымал; Жаңа бағытты ашыңыз**. Әр карточкада мұқаба, автор, рейтинг, қолжетімді дана, түсіндірме, сәйкес қызығушылық/пән, фактор кестесі және нақты `/Books/Details/{id}` сілтемесі бар. Жеткілікті дерек жоқ бөлім түсінікті бос күй көрсетеді.

Ұсыныстан кітап бетіне өткенде соңғы сәйкестік ұпайы бірге көрінеді. `RecommendationContextService` оны **15 минуттық** ASP.NET Data Protection токенімен қорғайды: токен ағымдағы viewer Identity ID-і мен нақты Book ID-іне байланған. URL-ді өзгерту, басқа адамға беру немесе басқа кітапқа қолдану жеке ұпайды ашпайды. Жай каталог беті осы контекстсіз ашылады; Book Details ұсыныс алгоритмін не LLM-ді қайта шақырмайды.

`appsettings.json` → `Recommendations`: `InterestWeight`, `SubjectWeight`, `HistoryWeight`, `PopularityWeight`, `ExcludePreviouslyBorrowed`, `PrioritizeAvailable`, `CandidateLimit`, `ItemsPerSection`. Толық есептеу формулалары [STUDY.md](STUDY.md) ішінде.

### Қосымша LLM түсіндірмелері

Қазіргі әдепкі режим — **Local Recommendation Engine**. Сыртқы API міндетті емес: ол тек жергілікті алгоритм таңдаған кітаптардың түсіндірме мәтінін толықтырады. **LLM-enhanced explanations** белгісі нақты жарамды жауап қабылданғанда ғана шығады. Тірі provider/API кілтімен тексеру орындалған жоқ; local fallback пен HTTP қателерін өңдеу тесттері бөлек бар.

Провайдерді қосу мысалы; `<...>` орнына өз мәндеріңізді беріңіз. Модельді провайдеріңіз бен аккаунтыңыз қолдайтын атаудан өзіңіз таңдаңыз:

```powershell
dotnet user-secrets set "Recommendations:Llm:Enabled" "true"
dotnet user-secrets set "Recommendations:Llm:BaseUrl" "https://api.openai.com/v1"
dotnet user-secrets set "Recommendations:Llm:Model" "<провайдер қолдайтын модель>"
dotnet user-secrets set "Recommendations:Llm:ApiKey" "<жеке API кілтіңіз>"
dotnet user-secrets set "Recommendations:Llm:TimeoutSeconds" "8"
```

Параметрлер: `Enabled`, `BaseUrl`, `Model`, `ApiKey`, `TimeoutSeconds`, `MaxExplanations` (әдепкі 12). Endpoint HTTPS болуы тиіс; loopback/private IP, URL ішіндегі credentials/query және автоматты redirects қабылданбайды. Бір batch сұрауы шектеулі уақытпен орындалады; API кілті жоқ, URL жарамсыз, timeout немесе provider қатесі болса, жергілікті түсіндірме сақталады және сайт жұмысын жалғастырады. Бұл параметрлер frontend-ке шығарылмайды.

Сыртқы сұрауда студент аты-жөні, email, телефон, студент нөмірі, ID және факультет жоқ. Еркін жазылған қызығушылық мәтіні орнына танылған академиялық ұғымдар ғана беріледі; кітап атауы/авторы/санаты және пән сәйкестігі қосылады. Модельге құралдар, авторизация немесе базаға өзгеріс енгізу мүмкіндігі берілмейді. Жауап тек белгілі кітап токендеріне қабылданып, Razor арқылы мәтін ретінде кодталады. HTTP келісімі [ресми Chat Completions құжаттамасына](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) негізделген.

## Бес міндетті есеп

`/Reports` тек Admin/Librarian үшін. Барлық есепте кезең, іздеу, санат/факультет сүзгілері, тиісті бағандармен сұрыптау, қорытынды статистика және 20 жолдан беттеу бар. Беру мәртебесі рейтингі есебіне қолданылмайды.

| Есеп | Құрамы және кезең мағынасы |
|---|---|
| Кезеңдер бойынша кітап беру | Күн/ай бойынша барлық, белсенді, қайтарылған, кешіккен берулер; `LoanDate` кезеңге кіреді |
| Танымал кітаптар | Кітап, авторлар, кезеңдегі беру саны, қазіргі қолжетімді дана, танымалдық орны |
| Кешіктірулер | Студент, кітап, беру күні/мерзімі, кешігу күндері, болжамды немесе бекітілген айыппұл, қайтару мәртебесі; кезең — беру күні бойынша |
| Оқырман белсенділігі | Студент, факультет, берулер/қайтарулар/кешігулер, соңғы әрекет, белсенділік ұпайы |
| Әдебиеттер рейтингі | Кезеңде жасалған ашық пікірлердің орташа бағасы, пікір саны, сол кезеңдегі беру саны, рейтинг орны |

Қайтарылған/кешіккен бағандары таңдалған берулердің бүгінгі немесе нақты қайтарылған кездегі күйін көрсетеді. Белсенділік ұпайы: `max(0, 3 × беру + 2 × қайтару − 2 × кешігу)`. Рейтинг пен танымалдық тең болса, кітаптар бір орынды бөліседі. Рейтинг жоқ кітапқа баға ойдан қойылмайды.

Кезеңдер: соңғы 7/30/90 күн, ағымдағы жыл, өз аралығыңыз. Аяқталу күні есепке кіреді; future күндер, кері аралық және 10 жылдан ұзақ кезең қабылданбайды. CSV және баспа нұсқасы ағымдағы сүзгіге сәйкес **барлық жолды** қамтиды. `/Reports/Export` UTF-8 BOM, дәйексөздерді escape ету және Excel формуласының басындағы `=`, `+`, `-`, `@` таңбаларын (бос орыннан кейін де) бейтараптандыру қорғанысын қолданады. `/Reports/Print` навигациясыз басып шығаруға бейімделген.

## Кеңейтілген талдау

`/Analytics` бетінде Chart.js негізіндегі жеті график бар:

1. Кітап беру динамикасы — line.
2. Кітап қайтару динамикасы — line.
3. Ең танымал 10 кітап — horizontal bar.
4. Кітаптардың санаттар бойынша таралуы — doughnut.
5. Кешіктіру динамикасы — bar.
6. Оқырман белсенділігі — толтырылған line.
7. Әдебиеттер рейтингі — bar.

Сүзгі өзгергенде `/Analytics/Data` SQL нәтижесін қайта алып, графиктер мен көрсеткіштерді жаңартады. 90 күннен ұзақ аралық айларға топталады; дерексіз күндер нөлмен толтырылады. Санат графигінде кезеңде берілген бірегей кітап әр өзінің санатында саналады. Кешіктіру графигі мерзімі кезеңге түскен кешігулерді санайды; бұл өткен күндегі қарыз қалдығы емес.

Он көрсеткіш: кітап атаулары, даналар, қолжетімді даналар, белсенді берулер, мерзімі өткендер, студенттер, белсенді оқырмандар, төленбеген/төленген айыппұл және орташа рейтинг. Қор/белсенді қарыз/берешек — қазіргі сәттің қалдығы; оқырман белсенділігі, төлемдер және рейтинг — таңдалған кезеңнің көрсеткіштері. Нақты мағынасы әр карточкада жазылған.

## Пікірлер және рейтингтер

Book Details ішіндегі пікір бөлімінде студент 1–5 баға қойып, мәтін жазады, өз пікірін өңдейді немесе жояды. Бір студент бір кітапқа бір белсенді пікір жаза алады; бірегей filtered SQL индексі оны бекітеді. Жою — `IsDeleted` soft delete; әкімші `/Reviews` арқылы жасырады/қайта жариялайды. Автордың өңдеуі әкімшінің жасыру шешімін өзгертпейді. Өзгерістер `RowVersion` арқылы қорғалады. Ашық орташа баға мен пікір саны SQL-ден есептеледі; жасырылған/жойылған пікір рейтингке, ұсынымдарға және есептерге кірмейді. Ашық тізімде студенттің жеке аты көрсетілмейді.

## QR, жапсырма және сканер

`/Copies/Details/{id}` нақты дананы ашады; `/Copies/Label/{id}` инвентарлық жапсырманы баспаға дайындайды, `/Copies/Qr/{id}` QR SVG береді. QR ішінде тек дананың бірегей `Barcode` мәні бар; студент пен қарыздың жеке деректері жазылмайды.

`/Copies/Lookup` штрихкод немесе инвентарлық нөмір бойынша іздейді. USB сканер мәтін енгізетін құрылғы ретінде сол өрісті пайдаланады. Камера тек «Камераны қосу» әрекетінен және браузер рұқсатынан кейін қосылады: қолдау болса native `BarcodeDetector`, болмаса жергілікті ZXing QR декодері қолданылады. HTTPS немесе `localhost` қажет. Рұқсат берілмесе немесе құрылғы қолдамаса, қолмен/USB іздеу сақталады. Беттен шыққанда камера тректері тоқтатылады.

Оқылған мәтін URL ретінде ашылмайды; ол тек өз `/Copies/Lookup` формасына жіберіледі. Дана табылған соң қолжетімділігіне сай «Кітап беру» немесе «Қайтару» әрекеті ашылады. QR/сканер және нақты беру/қайтару тек Admin/Librarian үшін. Физикалық камерамен сканерлеу әзірге жеке тексеруді қажет етеді.

## Ішкі хабарландырулар

SQL-backed хабарландырулар: сәтті беру, сәтті қайтару, бекітілген айыппұл, мерзімге 3 күн/1 күн қалуы және мерзімнің өтуі. Тақырыптағы қоңырауда оқылмаған саны мен соңғы хабарлар көрсетіледі; `/Notifications` тарихында біреуін немесе бәрін оқылды деп белгілеуге болады. Сұраулар ағымдағы Identity пайдаланушысымен шектеледі.

`WorkflowNotificationWriter` беру/қайтару/айыппұл хабарын сол бизнес транзакциясы аяқталғанға дейін сақтайды: кері қайтқан операциядан хабар қалмайды. `ReminderBackgroundService` іске қосылғанда және әр **30 минутта** мерзімдерді қарайды. SQL `sp_getapplock` және бірегей `DeduplicationKey` бірнеше серверде бір еске салудың қайталануын болдырмайды. Overdue хабары әр қарыз/мерзім үшін бір рет жасалады. Онлайн аккаунтпен байланыстырылмаған оқырманға ішкі хабар жіберілмейді. Email/SMS интеграциясы қосылмаған.

## Ақылды іздеу және интерфейс

Каталогтағы мәтін атау, автор, ISBN, баспа, санат, пән, тіл және сипаттамадан ізделеді. Автор/баспа/санат/пән/тіл және тек бос данасы бар кітап сүзгілері, атау/жыл/танымалдық/рейтинг сұрыптауы бар. Теру аяқталғаннан кейін 320 ms debounce арқылы `/Books/Results` жаңарады; алдыңғы сұрау тоқтатылады. Тор/тізім таңдауы browser localStorage ішінде сақталады. JavaScript болмаса, әдеттегі GET форма мен беттеу қалады.

Оқырманға жоғарғы навигация, қызметкерге ықшам басқару rail-і беріледі. Ашық/қараңғы тақырып, хабарлама toast-тары, растау диалогы, бос/жүктелу күйлері, responsive кестелер, keyboard focus және reduced-motion қолдауы бар. Chart.js/ZXing/Lucide негізгі файлдары `wwwroot/lib` ішінде жергілікті беріледі. Физикалық камера қолдауын өз құрылғыңызда бөлек тексеріңіз.

## Жаңа визуалды концепция: Editorial Digital Library

**EduLibrary — The Modern Knowledge Space**: жылы редакциялық кітап дүкені мен университет кітапханасының біртұтас ортасы. Негізгі беттер үлкен сәндік баннерлердің орнына кітаптарға, оқуға және нақты әрекетке назар аударады.

Дизайн токендері `wwwroot/css/site.css` ішінде орталықтандырылған. Ашық режимде cream `#F7F5EF`, forest `#18382F`, sage `#DDE5D8` және copper `#C56E4D` қолданылады. Қараңғы режим жеке forest палитрасына ауысады. Негізгі визуалды жүйеде күлгін/indigo түстері, градиенттер, glow және glassmorphism қолданылмайды. Manrope интерфейс қарпі мен Noto Serif редакциялық тақырыптары қазақ кириллицасын қолдайтын жергілікті WOFF2 файлдарынан жүктеледі; қаріпке сыртқы CDN қажет емес.

| Интерфейс бөлігі | Жаңа құрылымы |
|---|---|
| Оқырман және қонақ | Кең кітап каталогы, жоғарғы навигация, редакциялық мұқабалар, жеке оқу кеңістігі |
| Admin / Librarian | Ықшам басқару rail-і, кітапхана кеңсесінің тақырыбы, жұмыс тізілімдері |
| Dashboard | Сегіз ықшам көрсеткіш, беру тізілімі, кешіккен кітаптар күн тәртібі, қайтару дәптері және танымал әдебиеттер қатары |
| Оқырманның кітаптары | Типографиялық мұқабасы бар жеке кітап сөресі, анық қайтару мерзімі мен оқу жазбасы |
| Басқару тізімдері | Бірізді бет тақырыбы, ықшам сүзгілер, кең жолды тізілім, мәртебелер және жергілікті көлденең кесте айналдыруы |
| Формалар | Оқуға ыңғайлы өрістер, нөмірленген мағыналық бөлімдер, анық негізгі әрекет және сақталған валидация |
| Analytics / Reports | Жазық көрсеткіш жолақтары, тақырыпқа бейімделетін forest/sage/copper графиктері, CSV және таза баспа нұсқасы |
| Хабарландырулар | Оқылмаған күйі анық белгіленген хат-хабар журналы |

Құрылым: `_Layout.cshtml` рөлді анықтап, `_AppHeader`, `_StudentNavigation` және `_AdminNavigation` компоненттерін біріктіреді. `_Brand`, `_UserMenu`, `_FlashMessages`, `_BookCover` және `_BookCard` ортақ көріністерді қайта пайдаланады. `BookReviews`, `RelatedBooks` және `NotificationBell` ViewComponent-тері дайын ViewModel-дерді алады.

CSS жауапкершілігі бөлек: `site.css` — токендер мен жалпы навигация/контролдар; `catalog.css` — каталог, кітап мұқабасы және өнім беті; `management.css` — жұмыс тізілімдері, формалар, оқу жазбалары, графиктер, QR/сканер, пікірлер, хабарлар және баспа; `account.css` — авторизация мен профиль; `recommendations.css` және `reading-space.css` — жеке әдебиет таңдау мен оқу сөрелері. Бұрынғы `intelligence.css` файлы жойылды. Ұсақ мәтіндерде палитраны сақтайтын контрастты `--color-accent-text`, `--color-warning-text`, `--color-danger-text`, `--color-muted-ink` нұсқалары қолданылады.

Контент ені кішірейгенде бөлімдер бір бағанға көшеді; кең кестелер өз контейнерінде ғана айналдырылады. Басқару әрекеттері 44 px нысанаға, негізгі мәтін 14–16 px аралығына бейімделген. Тақырып таңдауы браузерде сақталады; `prefers-reduced-motion` анимацияларды азайтады. Бұл визуалды қайта құру SQL схемасын, рөлдік рұқсаттарды, сервис ережелерін және формалардың CSRF қорғанысын өзгертпейді.

## Қауіпсіздік және өнімділік

Identity cookie — HttpOnly; production-да HTTPS міндетті. Бес сәтсіз кіру әрекетінен кейін уақытша lockout қолданылады. Өзгеріс енгізетін сұрауларға жалпы anti-forgery тексеруі бар. Рөл шектеулеріне қоса студент деректері сервис query-лерінде өз Identity ID-імен шектеледі; DTO/ViewModel рұқсатсыз өрістерді сақтауға жол бермейді.

Маңызды айналым операциялары транзакцияда; RowVersion, unique/check constraints және FK шектеулері қатар өзгеріс пен тарихты қорғайды. Күтілетін deadlock/duplicate/concurrency қателері түсінікті бизнес хабарламасына айналады. EF параметрленген сұраулар, async/CancellationToken, `AsNoTracking`, SQL агрегаттары, batch жүктеу және беттеу қолданылады. Күндер/күй/байланыстар бойынша индекстер бар; еркін мәтін іздеуі қазір SQL `Contains`, бөлек full-text іздеу қозғалтқышы қосылмаған.

## Университетте қорғау сценарийі

Алдын ала demo аккаунттарын тексеріңіз. Жаңа кітап беру үшін бос дана және онлайн аккаунтпен байланысқан студент таңдаңыз; `student@edulibrary.local` бастапқы оқырманға байланыстырылған. Кешігу көрсету керек болса, беру күні мен мерзімін рұқсат етілген өткен күндерге қойыңыз; жаңа беру ескертпесіне «Қорғау демосы» деп жазыңыз.

1. **Librarian** аккаунтымен `/Account/Login` арқылы кіріңіз.
2. `/Dashboard` ашып, SQL-ден есептелген көрсеткіштер мен соңғы әрекеттерді көрсетіңіз.
3. `/Books` каталогында атау/автор/пән бойынша іздеңіз; сүзгі мен тор/тізімді ауыстырыңыз.
4. Нақты кітаптың **Book Details** бетін ашыңыз.
5. Қолжетімді **BookCopy** таңдап, оның бірегей инвентарлық нөмірін көрсетіңіз.
6. Сол дананы demo студентке беріңіз; беру және қайтару күндерін растаңыз.
7. Дана мәртебесінің **OnLoan** болғанын көрсетіңіз.
8. `/Students` → таңдалған студент профилінен жаңа borrowing history жазбасын ашыңыз.
9. Жүйеден шығып, **Student** аккаунтымен кіріңіз.
10. `/Recommendations` бетін ашыңыз.
11. Нақты каталогтан таңдалған кітаптар мен алты ұсыныс бөлімін көрсетіңіз.
12. Бір ұсыныстың түсіндірмесін және фактор/салмақ кестесін ашыңыз; нақты Local/LLM режим белгісін көрсетіңіз.
13. Карточканың **Кітапты ашу** сілтемесімен сол каталог кітабына өтіңіз. Қажет болса, өз бағаңыз бен пікіріңізді қосыңыз.
14. Librarian аккаунтына қайта кіріп, осы беруді **Қайтару** арқылы қабылдаңыз.
15. Мерзім кешіксе, бекітілген айыппұлды және ішінара/толық төлемді көрсетіңіз; кешікпесе, айыппұлдың жасалмайтынын түсіндіріңіз.
16. `/Reports` ашып, бес есепті, кезең/сүзгіні, CSV және баспа нұсқасын көрсетіңіз.
17. `/Analytics` графиктерін ашып, 7/30/90 күн не өз кезеңіңізге ауыстырыңыз.
18. `/Copies/Label/{id}` QR жапсырмасын көрсетіп, `/Copies/Lookup` арқылы кодын табыңыз. Камера қолдамаса, дәл сол штрихкодты қолмен енгізіңіз.
19. Student аккаунтына қайта кіріп, қоңырау мәзірі мен `/Notifications` тарихындағы беру/қайтару/айыппұл хабарларын, оқылды деп белгілеуді көрсетіңіз.

Бұл сценарий жаңа бизнес жазбаларын әдейі жасайды және олар тарихта сақталады. Негізгі базаны тазаламаңыз немесе бастапқы seed-ті қайта қоспаңыз.

## Шектеулер және орналастыру

Сыртқы LLM әдепкіде өшірулі және тірі API-мен тексерілмеген; жергілікті ұсынымдар оған тәуелсіз. Камера мен баспа сапасын нақты құрылғыда тексеру керек. Desktop/mobile өлшемдері Chrome Playwright арқылы тексерілді; Safari/Firefox пен физикалық мобильді құрылғы тексерілмеген. Email/SMS және банк төлем шлюзі қосылмаған; хабарландырулар ішкі, төлемдер қызметкер тіркейтін кітапхана есебі ретінде жұмыс істейді.

API кілттері, парольдер және local connection string-дер жауаптарға не Git-ке шығарылмайды; `appsettings.Local.json`, build/test artifacts `.gitignore` ішінде. Production үшін сыртқы құпиялар сақтау орнын, дұрыс HTTPS/SQL сертификаттарын, резервтік көшіруді және шектеулі SQL құқықтарын қолданыңыз. Басқа жобаға (`IntelligentProgrammingPlatform`) өзгеріс енгізілмейді.
